# V1 → V2: what changed and why

This repository is a port of
[`opencode-unlimited-usage`](https://github.com/ElectronBreach/opencode-unlimited-usage).
The WARP trick is unchanged; the places where OpenCode talks to providers moved.

## Summary table

| Area | V1 | V2 | Port decision |
|---|---|---|---|
| Request origin | TUI process (or its embedded server) | shared background server by default | force `--standalone` + disable the service |
| Error location | `opencode.log` | `session_message.data` in `opencode.db` | DB first, log fallback |
| Path discovery | hard-coded XDG paths | `opencode debug paths …` | resolve dynamically, keep classic fallback |
| Version flag | none | `--standalone` (2.x only) | inject only when major ≥ 2 |
| Global instructions | `~/.opencode/AGENTS.md` in practice | `~/.config/opencode/AGENTS.md` | credit injection dropped |
| Install command | `https://opencode.ai/install` | `https://opencode.ai/v2/install` | V2 installer, backup first |
| Binary | `~/.opencode/bin/opencode` | same | unchanged |
| Desktop/IDE | wrapper bypass possible | IDE integrations bypass the wrapper | documented limitation |

## File-by-file diff

### `install.sh`

- Uses the V2 installer and verifies the result is major ≥ 2.
- Backs up `opencode.db` (SQLite backup API), `auth.json`, `storage/` and
  `~/.config/opencode` before an upgrade. V1 → V2 migration is one-way.
- Runs `opencode service set disabled true`.
- Detects the real binary without ever selecting `~/.local/bin/opencode` (the old
  recursion bug).
- Writes sudoers entries for `systemctl stop/start opencode-unlimited-keeper` so the
  guard and hop can pause the keeper unattended.
- Uses `UBUNTU_CODENAME` for the WARP apt repo (Mint reports `zena`, not `noble`).
- Adds a removable PATH block so `~/.local/bin` wins over `~/.opencode/bin`.
- Fails early if `unshare -rm` is blocked.

### `uninstall.sh`

- `opencode service unset disabled` restores the V2 default.
- Uses the same dynamic `iptables`/`ip6tables` paths as the runtime.
- Removes the PATH block and `~/.config/opencode-unlimited/path.sh`.
- Keeps the V1 backup directory.

### `scripts/zen-lane.sh`

- `--standalone` when the binary is 2.x and the command accepts it
  (`service`, `upgrade`, `uninstall`, `debug`, `pair`, `serve`, `acp`, `version` are
  excluded).
- `pick_real()` refuses to exec the wrapper itself.
- `unshare -rm` failure and `/etc/hosts` bind failure are hard errors.
- Runs the binary as a child (not `exec`) so the scratch dir is removed.

### `scripts/zen-guard.sh`

- Primary detector: read-only SQLite query on `session_message`, matching
  `provider.free-limit`, `FreeUsageLimitError`, `Free usage limit reached`.
- Go/workspace/budget limits are excluded.
- Log tail remains as a fallback and now supports both a log directory and a log
  file.
- `/64` normalisation via `ipaddress`.
- Refuses to rotate when `OUC_LEAKGUARD` is missing.
- Resolves version and paths at startup; rejects a stale `OUC_REAL_BIN` that points
  at the wrapper.

### `scripts/zen-hop.sh`

- `/64` comparison instead of string comparison.
- Kill-switch gate before disconnecting.
- `sudo -n` for `systemctl` with a sudoers rule.
- Blacklists the old `/64` in guard state.

### `scripts/doctor.sh`

- Checks V2 version, `unshare -rm`, `service.json`, DB readability and wall count.
- Distinguishes a dead tunnel (safe, kill-switch blocking) from an IPv4 leak.
- Checks that `command -v opencode` resolves to the lane.

### `scripts/warp-keeper.sh`

Unchanged. It does not touch OpenCode.

### `AGENTS.md`

Dropped. The V1 credit-injection feature wrote to `~/.opencode/AGENTS.md`; V2 global
instructions live at `~/.config/opencode/AGENTS.md`, and the feature is unrelated to
IP rotation.

## Behaviour differences you will notice

1. **First V2 launch may migrate data.** Keep the backup.
2. **Pairing is unavailable** while the shared service is disabled.
3. **IDE integrations** (VS Code, JetBrains) do not use the lane.
4. **`opencode service ...` and `opencode upgrade`** run outside the private-server
   path by design.
